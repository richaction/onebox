# onebox 第一阶段验收记录

2026-11-15，Apple M2 Mac mini（24 GB）、macOS 27.2、Chrome 157（无头模式）、Node 26.13.1、Rust 1.99.1。前端锁文件实际安装 `solid-js@1.9.19`。

## 功能验证

| 检查 | 结果 |
|---|---|
| 前端 | 9 个测试文件、98 项通过。`pnpm typecheck` 和 `pnpm build` 通过。Vite 报告单个 JS 包约 537 kB，gzip 后约 184 kB。 |
| Rust | 格式检查通过，2 项单测通过，覆盖中文写入及覆盖读回、文件不存在时的错误。 |
| Chrome 块高与生命周期 | 3,000 块。被测块离屏后换成空占位并销毁内容 DOM，滚回后重建。可见及占位高度均为 80 px，外壳为 `flow-root`，上下 margin 均为 0。 |
| Chrome 编辑 | 12 个中文字经 Chrome 构字事件提交，构字期间滚动后正文完整。跨块 Enter、Backspace、两次撤销和鼠标拖选三块通过。浏览器 `copy` 事件的 `text/plain` 内容保留粗体和引用的 Markdown 标记。 |
| Chrome 文件流程 | 使用模拟 Tauri IPC 验证打开、800 ms 自动保存、另存为、关闭前写回和只读保护。写入失败时保留草稿、拒绝切换和关闭。写入重叠时按顺序落盘。 |
| macOS 桌面 | `pnpm tauri dev` 正常启动。用系统对话框打开临时 Markdown，插入中文后自动写回。⌘⇧S 生成与原文件字节一致的副本。在 3,000 块文件中滚动到第 97–116 段再滚回，原内容恢复。⌘W 和 ⌘Q 均在退出前写回最后一次编辑。 |
| 桌面只读和互操作 | 表格文件显示「只读」，另存为不弹出。原文件 SHA-256 前后一致。Typora 成功打开另存副本，标题、粗体、中文和列表均正确显示。 |

macOS 桌面测试确认了中文文本的编辑与写回。系统输入法的连续构字尚未通过真机验证。

## Chrome 性能

用短中文段落生成三个精确字符数的样本。每档重新加载页面，从顶端开始以约 2,300 px/s 连续滚动 4.5 秒，同时采集 Chrome DevTools trace。帧间隔来自 `requestAnimationFrame`。元素数、可见块数和视口事务计数来自 `window.__oneboxMetrics()`。

| 字符数 | 顶层块 | 滚动后可见块 | 页面元素数 | 平均 fps | P95 帧间隔 | 最长帧间隔 | 可见性事务峰值 | 滚动期 nodeView 创建 / 销毁 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 10,000 | 203 | 12 | 234 | 60.0 | 16.8 ms | 16.8 ms | 1.4 ms | 294 / 294 |
| 100,000 | 1,983 | 12 | 2,014 | 60.0 | 16.8 ms | 16.8 ms | 3.1 ms | 294 / 294 |
| 1,000,000 | 19,445 | 13 | 19,477 | 59.8 | 16.7 ms | 33.3 ms | 10.2 ms | 253 / 253 |

在所有块上生成可见性装饰时，百万字符档约为 1.8 fps，可见性事务峰值约为 1,265 ms。改成只为可见及选区内的块生成装饰后，10 万字符档未出现超过 25 ms 的帧间隔，百万字符档出现一次 33.3 ms 的帧间隔。百万字符文档从解析到更新视图的同步时间约为 657 ms。

按 Plan 的 10 万字符触发条件，本阶段保留方案 A。百万字符档仍有一次掉帧，每个顶层块保留一个占位外壳，DOM 元素数随块数线性增长。这两个指标仍达不到上游技术方案的性能红线。
