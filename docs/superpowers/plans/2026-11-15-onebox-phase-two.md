# onebox 第二阶段计划

以 [第一阶段验收](2026-11-15-onebox-foundation-verification.md) 和 [技术路线图](../../高性能块式Markdown编辑器技术方案.md) 为起点。继续使用 Tauri v2、SolidJS 稳定版 `1.9.19` 和单一 ProseMirror 文档模型。编辑器内的块操作与 Markdown 语法是同一组编辑能力的入口，磁盘上的 `.md` 是可直接交给其他编辑器的源文件。

## 1. 块编辑与 Markdown 兼容

- [x] 支持 GFM 表格、任务列表和标准图片语法，以及 Typora、Obsidian 通用的 `[^id]` 脚注。保留列表嵌套与完成状态、表格列对齐、图片替代文本和脚注标签。遇到可能丢失的语法时继续只读打开。
- [x] 在可编辑块内键入 `/` 打开可筛选的命令菜单。支持方向键、Enter、Esc 和鼠标。右键块内任意内容打开同一组适用的命令，保留编辑位置与选区。
- [x] 提供段落、标题、无序列表、有序列表、任务列表、引用、代码块、分隔线、表格、图片与附件入口。支持 `###` 加空格、`- `、`1. `、`> ` 等 Markdown 输入规则。组合输入期间不触发命令，关闭菜单后可继续原处输入。命令和 Markdown 快捷输入可撤销。
- [x] 验证打开、编辑、保存、重新打开的语义一致性。导出的正文使用 CommonMark、GFM 与双方支持的脚注语法。保存结果在 Typora 和 Obsidian 中验证链接、图片、表格、任务项与脚注。

## 2. 附件与文档操作

- [x] 附件通过插入文件、粘贴或拖放导入。托管文件放在文档同目录的 `assets/` 中，通过相对 URL 引用。图片写成 `![替代文本](assets/…)`，其他附件写成 `[文件名](assets/…)`。文档尚未命名时先选择保存位置。正文保持可移植，不写私有块 ID、绝对路径或二进制数据。
- [x] 支持文档内联预览。渲染组内的本地图片按需读取，普通附件显示文件名并提供打开入口。打开已有的标准 Markdown 时保留其合法相对路径和外部链接。文件列表默认隐藏 `assets`，文件可通过正文引用访问。
- [x] 在编辑器内移动、改名、复制或另存为文档时，自动搬移或复制所引用的附件并按目标位置维护相对链接。相同内容可以复用，同名不同内容保留双方，普通相对文档链接随文档的位置更新。共享或外部引用仍需有效。
- [x] 写入先准备附件，再提交目标 Markdown。移动操作在目标文档和附件可读后才移除源文档。遇到缺失附件、写入错误或冲突时保留源文档与草稿，避免半套结果。源附件保留，防止其他文档的已有引用被破坏。

## 3. 百万字符性能

- [x] 用 Rust 和 `pulldown-cmark` 在后台解析长文档，并分批把顶层块传给前端。解析时保留完整文档上下文，以正确处理跨位置的引用、脚注及容器块。先显示首屏，再分批建立完整编辑状态，加载期间防止局部文档被保存。
- [x] 将大文档的 Markdown 序列化与校验移出 UI 主线程。批次、自动保存及附件导入应在切换文件时安全收尾，且能够丢弃已取消加载的结果。
- [ ] 在桌面端测量 10 万和 100 万字符的首屏、可编辑时间、输入和滚动。使用纯文本、多种块混合及含附件的语料，覆盖连续输入、中文构字、滚动、撤销和自动保存。以 60 Hz 下滚动接近 60 fps、P95 帧间隔不超过 20 ms、打开和保存期间界面可交互为验收目标。记录超过 50 ms 的 UI 主线程任务、DOM 元素数和重现步骤。
- [ ] 现有占位方案以第一阶段结果为基线。如果百万字符仍阻塞交互，实施设计中的方案 B，让编辑视图只挂载视口及缓冲范围的块。升级需保留跨块选区、撤销、剪贴板和构字，验证 DOM 数量受视口控制。

## 实施顺序

1. 补齐 Markdown 节点与往返测试，接入共享块命令和两个菜单入口。
2. 加入 Rust 后台加载与分批挂载，复测 10 万和百万字符，针对实际瓶颈调整视图。
3. 接入托管附件、工作区文件列表和移动／复制事务，用临时目录验证相对链接与部分失败。
4. 用真实 WebView 和第三方编辑器复验，记录验收数据和仍存在的限制。

## 本轮验收

macOS WebView 使用临时工作区验证了图片插入与预览、隐藏 `assets/`、跨目录复制与移动。目标目录复用同一张图片，普通文档链接从 `Other.md` 改为 `../source/Other.md`。另在百万字符文档中编辑、滚出、滚回并确认磁盘写回。Typora 和 Obsidian 都打开了复制件，确认图片、表格、任务项和脚注可显示。Obsidian 阅读模式解析出移动后的相对文档链接。

Chrome 157 无头模式在 Apple M2 上使用由中文段落、标题、引用、列表、表格和代码块构成的混合语料。文件 IPC 使用模拟传输，真实 Markdown 序列化在 Worker 中执行。持续滚动 4.5 秒，滚动输入为每帧 36 px。自动保存时间包含约 800 ms 防抖，从开始发送测试编辑到 Chrome 模拟写入完成。

| 字符数 | 文档块 | 滚动后页面元素 | 平均 fps | P95 帧间隔 | 前端可编辑时间 | 编辑至写入 |
|---|---:|---:|---:|---:|---:|---:|
| 100,000 | 2,732 | 2,825 | 60.0 | 16.8 ms | 127 ms | 1.00 s |
| 1,000,000 | 26,959 | 868 | 60.0 | 16.8 ms | 914 ms | 1.15 s |

百万字符档原先在逐块占位下约为 37 fps。当前大文档每组最多放 64 个原始块，远离视口的组只留一个占位，导出时展开组内内容。滚动样本未观察到超过 50 ms 的主线程任务。序列化器同一轮输出分段缓冲，百万字符的编辑到模拟写入从约 6–7 秒降为 1.15 秒。每组占位仍随文档增长，完整的滑动窗口方案保留为压力测试后的升级选项。

仍需覆盖不同形状的百万字符语料、桌面系统输入法持续构字、桌面粘贴与拖放文件，以及长时间操作后的内存稳定性。
