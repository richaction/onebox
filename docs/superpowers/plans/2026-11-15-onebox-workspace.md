# Onebox 工作区计划

工作区以用户选中的本地文件夹为根。左侧沿用 Typora 的目录层次，把文件夹和 Markdown 文档直接映射到磁盘，并采用 Notion 式的拖动、行内反馈和右键操作。编辑器仍使用 SolidJS 稳定版 `1.9.19`，磁盘上的 Markdown 和附件可以直接交给 Typora、Obsidian 等编辑器。

目录树和批量路径变更沿用已有的 Markdown 文档操作和 SHA-256 附件命名。交互参考 [Typora 文件管理](https://support.typora.io/File-Management/) 和 [Notion 侧栏](https://www.notion.com/help/navigate-with-the-sidebar)。

## 1. 左侧工作区

- [x] 显示可展开的文件夹、Markdown 文档和空目录。默认隐藏名为 `assets` 的目录及隐藏系统项。把正在打开的文档高亮，跨目录移动后选中它的新位置。
- [x] 支持拖到任意目录，包括根目录，也提供键盘可用的「移动到」入口。拖动时高亮目标，悬停可展开目录。重名和权限失败会显示原因，自身及子目录在目标选择器中不可选。
- [x] 按需读取目录内容。展开操作只读取当前目录，移动所需的 Markdown 扫描与哈希计算在 Rust 后台执行。

## 2. Markdown 与附件一起移动

- [x] 单独移动 Markdown 时先保存正在编辑的文档，解析有效的本地链接，复制实际引用的附件到目标文档同级的 `assets/`，同时更新 Markdown 相对链接。保留普通文档链接的目标，以及链接片段和查询参数。
- [x] 目标已有 `assets/` 时合并附件。用 SHA-256 对文件内容做流式哈希，可复用内容相同且扩展名相容的既有文件。同名不同内容的附件可共存。源附件保留供现有链接使用。
- [x] 文件夹移动保留子目录、Markdown 和 `assets/` 的相对结构。继续使用有效的内部相对链接。跨子树的相对链接和工作区内指向已移动文档的链接自动重算。
- [x] 预检物理路径、权限、同名文件和循环移动。源文本级重写只替换标准 Markdown 链接的目标，保留正文、换行、前置元数据和代码。单卷文件夹移动使用系统的原子改名，跨卷移动先验证目标副本再移除源目录。并发修改或写入失败会中止移动并尝试恢复已写入的变更。

## 3. 附件预览预留

- [x] 保留通过文档路径和相对链接解析附件的入口。新增预览器时按媒体类型接入。图片继续走现有的按需内联加载，普通附件可交给系统默认应用打开。
- [ ] PDF 与 Word 的渲染器、交互和安全边界另行确定。未来的预览与 Markdown 引用使用同一附件路径，索引或缓存无需写入正文。

## 验收记录

- macOS WebView 在临时多级工作区中移动了正在打开的 Markdown 和含多个 Markdown 的文件夹，侧栏跟随当前文档。源附件仍在，目标复用了原有图片。Typora 能显示移动后的图片，跟随内部链接到达正确文档。
- 用单独挂载的 HFS+ 磁盘映像验证跨卷文件夹移动。用键盘选择目标并确认，检查源目录已移除、空目录与附件保留、两侧 Markdown 链接正确更新。
- Chrome 隔离环境用指针事件验证拖放、高亮、重新打开当前文件，并验证键盘、取消、冲突提示与 320 px 宽度布局。Rust 测试覆盖未打开文档、去重、同名不同内容、权限失败、子目录冲突、源文件并发变化和提交后的回滚。
- Chrome 使用模拟文件 IPC、真实 Markdown 保存 Worker。显示 100 个目录时，百万字符混合文档约 0.92 秒可编辑，滚动约 60 fps，P95 帧间隔 16.7 ms。输入到模拟写入完成约 1.14 秒，包含 800 ms 防抖。
